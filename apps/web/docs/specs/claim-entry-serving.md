# Static serving interface

server/static.mjs is the proposed executable Node22 built-ins-only static server. Its arguments are --root, --port, --prefix, --claim-path, --core-origin, --provider-origin and --matrix-domain (the domain every organisation's homeserver and LiveKit server sit under, console ADR-0012: a lowercase DNS name of two labels at least, with no scheme, port, wildcard or trailing dot). connect-src names, under https://*.{matrix-domain}, the paths /.well-known/matrix/client, /_matrix/ and /_kodera/rooms/token, and under wss://*.{matrix-domain} LiveKit's /rtc, /rtc/v1, /rtc/validate and /rtc/v1/validate; no source under the wildcard is a bare host. For the local stack only, --allow-loopback (a flag without a value) admits --homeserver-origin (an http or https origin on this machine: its /_matrix/ and /_kodera/rooms/token) and --livekit-origin (a ws origin on this machine: LiveKit's four paths); without --allow-loopback either one stops the server before listening, as does --allow-loopback without either, and no other homeserver or LiveKit origin is accepted. No origin/prefix is inferred from requests. Only explicit HTTPS origins (or the loopback origins above) without userinfo/path/query/fragment are admitted; prefix/claim paths are normalized nonsecret deployment inputs and must match the built app/Core invitation configuration. It binds loopback; an actual listener/host/edge needs separate operator authority. It is not a business API or proxy. Port0 is an explicit hosted-test fixture input.

The single startup JSON line reports event:listening, host from the actual server.address().address and its bound port. Hosted acceptance requires127.0.0.1 and source review verifies this is the actual address. A successful connection to that address alone cannot prove an exclusive loopback bind or deployed network exposure.

The root is an immutable built tree. GET/HEAD serve files and extensionless SPA fallback inside the configured prefix. Missing files/assets/API paths do not become successful HTML. Other methods fail405 with Allow GET, HEAD. Malformed/traversal/encoded-separator or absolute-form targets fail400; symlink escape fails403. Errors and HEAD retain the same application-response security policy. No directory listing, outbound proxy, upload, auth/claim operation, query/access logging or persistent store exists. Missing/invalid configuration stops before listening without echoing values.

Port is canonical decimal0..65535; / is an explicit valid prefix. Origin inputs require an explicit HTTPS prefix, nonempty raw authority without @, no whitespace/backslash/Unicode Cc controls and no raw query/fragment delimiter, even an empty one. Only the root trailing slash is optional. This rejects parser-normalized ambiguous inputs before trusted policy tokens are constructed.

# Source HTTP policy

Responses carry Referrer-Policy:no-referrer, Cache-Control:no-store and X-Content-Type-Options:nosniff. One exception: a content-hashed file served from /assets/ with status 200 is cached for a year and may be sent precompressed ([`asset-caching-and-compression.md`](asset-caching-and-compression.md)); every document, fallback and error stays no-store. CSP restricts scripts to self with no inline/eval/inline-handler permission; default/font/image/style elements are self, object/base are none and forms self. Connection sources are self plus explicit Core /api/v1/ and provider /realms/ bases; frame sources are self plus that provider realm base. Protected claim entry and the distinct /auth/claim-callback have frame-ancestors none. Only the exact ordinary /auth/callback may be same-origin frameable for existing silent SDK transactions; it cannot drain a claim envelope or replace the protected callback.

The closed directive inventory is default-src, script-src, script-src-attr, style-src, style-src-attr, img-src, font-src, object-src, base-uri, form-action, connect-src, frame-src and frame-ancestors. Duplicate/additional directives are refused by acceptance, including script-src-elem/style-src-elem/worker-src overrides that could otherwise bypass the asserted fallback values.

Styles are as strict as scripts: style-src is self alone (no unsafe-inline, hash or nonce) and style-src-attr is none, so a style attribute in markup, one written with setAttribute, and an injected style element are each refused. A value known only at run time (a progress width, a dragged sidebar width, a meter) is set through the CSSOM (src/ui/cssom.ts), which CSP does not govern, and product code passes no style prop (eslint.config.js). Radix's scroll lock adopts a constructed stylesheet instead of injecting a style element (src/ui/csp/styleSingleton.ts, aliased for react-style-singleton). The constant style element @radix-ui/react-select's viewport renders is removed at build and its rule ships in src/index.css (scripts/vite/radixSelectViewportStyle.ts; tests/unit/serving/radix-select-style.test.ts binds it to the installed package). tests/e2e/strict-style-csp.spec.ts serves a mock build through this server and opens Tooltip, DropdownMenu, Popover, Dialog, Select, the audio dock and Theme Studio with zero securitypolicyviolation events. No provider frame compatibility or MSW-only exception is asserted. Verify the actual emitted app and installed SDK in separately admitted hosted browser acceptance before connecting entry transport.

# Acceptance and evidence limits

tests/unit/serving/headers.test.ts exercises the actual CLI via owned loopback HTTP, finite built-file fixtures and an owned proxy-detection sink. It covers GET/HEAD protected/static/SPA/error policy, ordinary callback separation, configured destination tokens, no callback logging, invalid config, prefix isolation, methods, traversal and symlink/proxy refusal. Initial missing CLI is a new-interface failure, not a reproduced existing production regression. Source-bound negative controls and exact-head hosted qualification are required before publication; static metadata or a mock that writes expected headers is insufficient.

Asset and400/403/404/missing-index responses are checked with HEAD as well as GET. Config coverage includes canonical port refusals, root-prefix validity, raw query/fragment delimiters and controls. Complete stdout/stderr assertions wait for child close, including the owned valid child used for callback requests; exit alone does not establish complete stdio. Any later mutation campaign remains separately admitted and source-bound.

Sticky stdout/stderr overflow ledgers fail even if an over-limit chunk is discarded; unexpected serving termination is also a failure outside explicit cleanup. The checks run after close before log-absence or config-refusal claims. An adversarial Host/Forwarded/X-Forwarded-* request must leave configured policy tokens unchanged. Later source-bound negative controls include oversized late output, early termination and a bind-all-interfaces mutation, without external network probing.

Fixture cleanup runs in finally even when an observability assertion fails. The root-prefix positive child receives a synthetic ordinary callback query and is also checked after close for startup-only stdout and empty stderr, without callback query data.

The owner-adopted startup rule permits only the navigation document and at most ONE same-origin self-contained external bootstrap before verified fragment/envelope cleanup. This server alone implements no capture, storage envelope, SDK callback routing, ownership grant or registered-factor enrollment. One bounded ten-minute/non-sliding envelope, one redirect, verified pre-SDK deletion, explicit consume, unresolved recovery and SUBMISSION_HELD remain. Source HTTP proof does not establish browser eager-fetch ordering, deployed TLS/edge/CDN headers, real provider/client registration, commercial/readiness authority or a release. All require separate source-bound and operator evidence.
