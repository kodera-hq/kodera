## Component and token map

One workspace navigation component and one outline glyph set serve both canvases. One Markdown draft editor serves local preview documents and the live session draft. EspaceLiveView owns the call controller independently of canvas choice and draws it through `VoiceCallDock.tsx`; moving its presentation does not create a new connection.

Use c-surface/c-sunken/c-muted for planes, c-ink/2/3 for hierarchy, c-ok-soft with c-ink for selected rooms, c-action for primary actions, c-warn-soft/c-warn-ink for annotation, c-inverse/c-on-inverse for calls, and c-bad for leave. Space, radii, type weights and layout widths come from the shared package. Add an 800-weight heading token and load its licensed local font face. Names retain the available 700 face: the reference's 750 is not a licensed static weight currently loaded. No exact source font is identified. The product keeps a wider resizable sidebar than the 170px embedded landing, because real room names, counts and audio occupants need room. No illustrative portraits enter customer flows.

## Acceptance criteria written before implementation

- Both canvases share every navigation destination, with explicit unsupported states.
- A real selection, including a selection in the middle of text, is formatted without altering unrelated content. Undo/redo and heading/list/task state follow that selection. Links require an admitted HTTP(S) URL; HTML is escaped.
- Draft edits survive conversation → document → conversation and channel switches within their existing lifetime; no server-save claim is added.
- An existing call survives canvas navigation with the same controller; mute/deafen/leave still invoke it. No automatic media request is introduced.
- The dock spans the workspace sidebar and content. Mobile retains navigation disclosure, complete toolbar, comments below content and usable controls.
- Browser captures at 1440×1000 and 390×1000 cover light FR and dark EN before/after. Functional checks and screenshot inspection are reported separately.
- Existing offline/loading/empty/error/permission states and auth boundaries remain intact.

## Native assessment

The desktop README describes Rust backend seams and self-host preflight, not a running shell. iOS App/DocsWorkspaceCard.swift and VoiceCallDockCard.swift, and Android session/DocsWorkspaceCard.kt and VoiceCallDockCard.kt expose local preparation/coordinator states; their READMEs explicitly separate these from live channel/media delivery. Apply shared generated colors/type hierarchy and platform-sized controls, native disclosure and a persistent call owner when those flows are admitted. Do not shrink the web sidebar or add unqualified media/provider integration. Native implementation and physical-device accessibility evidence are separate follow-ups; this slice makes no native readiness claim.
