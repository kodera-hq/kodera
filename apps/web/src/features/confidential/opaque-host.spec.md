# Opaque confidential host snapshots

Status: Specification written before implementation; read-only source and browser cases are implemented and await independent review and hosted qualification. Read-only worker-private framing and outer-storage recovery; no native bindings, inner authentication, worker runtime or product messaging/media integration. Source/runtime qualification pending.

## Scope and authority

Add only opaque-host.ts, this specification and the managed confidential-opaque-host.spec.mjs browser suite. Existing local-state, Core contract, Rust, graph, CSP, dependencies, workflows, UI and previous tests remain unchanged. No native create/restore/sign/send/rewrap/upgrade method, injectable native bridge, success stub, seed getter, raw KWE1/header/provider/outbox export or generic withSeed callback exists in this increment.

Accepted context is a synchronous immutable copy of non-nil canonical lowercase owner/organisation/membership UUIDs. Capture the trusted ticket's checkCurrent method and receiver before awaiting; it returns boolean synchronously and receives no arguments/secrets. Recheck before and after every awaited store operation and immediately before returning a descriptor/handle. An observed false/throwing/nonboolean ticket permanently closes the capsule, its room and owned store, clears owned buffers best effort and requires a fresh authoritative read. Making that ticket valid later never revives an old object. Owner incarnation remains independently fenced inside the real outer store. Current Core admission/READ authority, whole-store rollback, same-origin/XSS and hardware guarantees are not supplied here.

A ticket callback may synchronously close an exposed device or child. Recheck permanent device failure and the described child's lifetime after invoking that callback, before accepting its result or returning output. The first permanent device failure wins even if a callback returns false after closing. Closing only a child leaves the parent live and releases that child's slot; a true ticket cannot revive the closed child.

## API and ownership

The first export surface is one factory, opaque interfaces and closed code-only errors. Classes/constructors/parsers remain module-private; descriptors are frozen copies of public routing identity/generation/format with native=unavailable and innerAuthentication=not-performed. Parsed seed/key-ID/nested state/anchor/pending bytes never appear in descriptors, JSON, errors or callbacks.

Factory ownership must prevent database bootstrap writes on read refusal. The existing openConfidentialState implementation can create an empty schema/capacity entry when its database is absent; an advisory databases() preflight cannot eliminate a deletion race. Parent-approved closed boundary: openStoredContext takes ownership of an already-open ACTUAL ConfidentialStateStore instance, verified against the imported class, with imported implementation methods captured instead of caller-injected per-instance methods (no arbitrary injected store). It never opens/initializes a database, generates entropy, writes or deletes a record. The caller transfers that connection exclusively; success, empty context, close and refusal all release ownership correctly. Existing accepted-owner store setup is a separate explicit prerequisite. This capsule does NOT prove zero writes across opening an uninitialized IndexedDB database; that upstream schema-bootstrap behavior lies outside the transferred-connection contract.

The caller must cease using the transferred connection, including from its ticket callback. The factory exposes no new capsule before its final callback and construction. Continued external use or closure of the transferred store violates exclusive ownership; this capsule provides no synchronous store-liveness proof for that misuse after a completed read. No Foundation liveness API or probe transaction is added here.

- openStoredContext(store, acceptedContext, ticket): call the real readUniqueDeviceVault for captured org/member. Empty context returns null and closes the transferred connection. Verify selected owner/context/public key/generation, empty device outbox and strict KWE1 shape. Copy into private owned buffers, clear temporary returned snapshots and check the ticket again before returning. Frame admission does not infer whether the hidden native vault is pre-admission None or admitted Some.
- device.describe(): only copied owner/org/member/public key/generation and unavailable/not-performed flags, after current/closed checks.
- device.openStoredRoom(roomId): capture non-nil canonical UUID and ticket; use the selected device's exact scope and actual store.read. Strictly dispatch by freshly read generation. Admit ONE retained room and one in-flight room request; competing opens refuse capacity until explicit room close, with no eviction. Empty room returns null. After possible I/O/framing failure, close/quarantine instead of silently retrying. A missing/invalid ticket always permanently closes.
- room.describe(): copied room ID/generation plus initial/durable discriminator and unavailable/not-performed flags, after parent/current/closed checks. No anchor/header/pending body or native operation getter.
- close() on either handle is idempotent. Device close closes its room/store and owned buffers immediately; room close clears its buffers and releases its parent's one-room slot. Close never reopens or returns private bytes.

The one-room profile retains at most36MiB of logical owned payload buffers per device capsule, including device private state and the room checkpoint/outbox. This is an explicit first-increment admission bound, not measured RSS; bounded transient store/decrypt/copy/browser allocations are separate. Future global actor handle limits remain integration work. Use fixed owned copies before awaits, reject shared/detached buffers and synchronously snapshot any accepted resizable ordinary view. Never wipe caller-owned setup input. Best-effort clearing does not prove universal JS/WASM/browser/forensic erasure.

## Closed framing

KWE1 is magic4, immutable ID16, software seed32, u32be nested length4, then exact KDV1. Prefix56; total92..17825792; nested36..17825736. Validate bounds before copying, exact declared remaining length and KDV1 magic, no trailing/unknown-version/raw-KDV1 fallback, and no device pending sends. The recoverable software seed is distinct from the outer non-extractable AES-GCM CryptoKey; no new KDF is introduced and reads never regenerate keys/IDs.

KRI1 has fixed73-byte header: magic@0(4), kind@4(1), epoch@5(8), sequence@13(8), UUID@21(16), Welcome SHA256@37(32), nested KMS1 length@69(4), then KMS1@73. Total109..14680137; nested36..14680064. Read u64 as BigInt and reject above9007199254740991 before Number conversion. Creator kind0 requires epoch0/sequence0/all-zero UUID and digest sentinel. Welcome kind1 requires positive safe epoch/sequence and non-nil UUID; binary/text conversion round-trips canonical RelayId grammar. Digest is exactly32bytes, not proof of a real consumed Welcome. Unknown kind/version/truncation/length/trailing/unsafe integers refuse before oversized copies.

Fresh record generation1 REQUIRES KRI1 plus empty room pending sends. Generation>=2 REQUIRES KDR1 with33..17825792 transport bytes and bounded opaque pending sends (32items,64KiB each,1MiB aggregate, unique canonical UUIDs). Never fall back to another format, raw KMS1 or signer regeneration. Inner KDR1/outbox manifest equality requires later actual Rust authentication and is not claimed by this opaque loader.

Rust constructors admit KDV1/KMS1 at36bytes and KDR1 at33bytes as bounded transport frames; magic/length admission proves no inner AEAD/provider/MLS validity. Outer store AEAD protects scope/incarnation/generation and complete opaque payload. The KRI1 anchor is protected historical evidence, not a current Core READ grant. Actual native operations remain unavailable.

## Later closed native host-write contract

This increment exposes no callable native writer or public framing encoder. Later real compiled bindings must own an unforgeable closed native-result capability and capture an immutable witness for EACH exact create/join invocation, tied to owner/org/member/device/room/epoch and exact consumed Welcome input/digest. No ambient lastWelcome slot or arbitrary main-thread anchor assertion.

A real future native callback must validate matching scope/key/generation/initial-room epoch and witness, then atomically CAS updated private KWE1 plus exact KRI1 initial room in one existing strict outer-store batch. No anchor side-write, plaintext seed record or pointer follows the callback. Post-oncomplete current-ticket check precedes native output/quarantine release; conflict/cancel/unacknowledged commit requires authoritative reload. Gen1KRI1 and gen2KDR1 crash truth comes from stored generation, never callback assumptions. Pre-admission recovery uses actual None and blocks room operations; admitted Some requires fresh independent Core match. These are future integration requirements, not simulated successes here.
