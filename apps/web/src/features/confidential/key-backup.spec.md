# Local zero-knowledge key backup

Status: Implemented for user-held encrypted `.kvkb` archives through dedicated workers. Server key-backup storage, server freshness and automatic cross-device admission are deferred.

Only a transferred `vaultPort` carries unsealed vault/epoch bytes between the vault and backup workers. Control RPC accepts recovery input and sealed capsules only; it cannot accept or return plaintext vaults or AES keys. A dedicated vault worker reads the existing account/organisation/membership device checkpoint and pending record, including its native wrapping seed, directly from the local encrypted store. Import refuses any existing device, stale owner tombstone or wrong context. Import restores local storage only; current Core authority and native validation remain necessary before device use.

`KVKB1` is five ASCII magic bytes, a big-endian 32-bit canonical-header byte length, a canonical JSON header, then ciphertext with a full 16-byte GCM tag. The header is `["kodera-zk-key-backup",1,organisationId,accountId,backupEpoch,kdfKind,iterations,saltBase64,ivBase64]`. AAD is the first seven fields, byte-for-byte canonical. Salt is 16 random bytes, IV is 12 random bytes. HKDF-SHA-256 derives a non-extractable AES-256-GCM key, with domain-separated context information. Recovery-key mode has iterations 0 and a worker-generated 32-byte key displayed once as sixteen four-hex-digit groups and a two-byte SHA-256 checksum group. Import validates checksum before KDF/decryption. Passphrase mode uses PBKDF2-SHA-512 with 600,000 through 2,000,000 iterations and at least twelve characters, then HKDF-SHA-256. The upper bound prevents capsule-driven excessive work; weak iteration counts are never retried.

All owned temporary secret/recovery/plaintext byte buffers are cleared in finally paths. CryptoKey handles are non-extractable and dropped after use; JavaScript strings, browser internals and copies outside worker ownership cannot be universally erased. Human recovery strings intentionally reach the dedicated UI and are cleared on dismissal, navigation, sign-out and accepted erasure. Archives already exported remain user-held. No backup metadata is persisted in browser storage; live workers, pending operations, file URLs and recovery display are retired through local-session cleanup. A restored local checkpoint is not a server freshness receipt or proof of admission.

Acceptance tests cover both real WebCrypto roundtrips, checksum-before-KDF refusal, bounds, randomization, principal/epoch/AAD tampering, wrong credentials, non-extractable derived keys, transfer-only plaintext routing, cleanup/error/close races, document-context/import fences, archive export/import and honest UI status. Real IndexedDB/browser qualification remains hosted; no local browser or native build is required.
