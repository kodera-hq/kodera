# Kodera Enterprise Edition (`ee/`)

Status: Active

This directory holds commercial **Enterprise Edition (`KODERA_EDITION=enterprise`)** capabilities governed by [`ee/LICENSE`](./LICENSE) (Samouraï Coop Commercial License, `LicenseRef-Kodera-EE`).

## Our Buyer-Based Open-Core Principle & Clean-Room Boundary

Kodera follows a strict, transparent boundary inspired by GitLab, Mattermost, and Grafana (see [`GOVERNANCE.md`](../GOVERNANCE.md)):

1. **Clean-Room Isolation:** `ee/` is loaded strictly when `KODERA_EDITION=enterprise`. Open-source packages (`apps/*`, `packages/*`, `extensions/*`, `deploy/community/`) contain zero static imports of `ee/` and run standalone in Community Edition (`KODERA_EDITION=community`, the default) with zero degraded collaboration features. When `KODERA_EDITION=community`, requests to `/api/v1/ee/billing*` return `404` (`application/problem+json`) and requests to `/api/v1/ee/*` governance endpoints return `403 {"detail": "Enterprise Edition required", "code": "enterprise_edition_required"}`.
2. **Never cripple individual or team collaboration in Community Edition:** Channels, DMs, voice/video rooms, screen-sharing, file sharing, standard security updates, Passkeys, `#proximity` client check-in codecs, and the Extension SDK live in the open-source tree (`Apache-2.0` / `AGPL-3.0-or-later`) forever.
3. **Enterprise governance, compliance & billing pillars live in `ee/`:** Features built specifically for CISO, procurement, and multi-entity corporate governance require a commercial subscription at **[kodera.io](https://kodera.io)**.

## Implemented Enterprise Edition Modules

- **[`ee/edition.py`](./edition.py), [`ee/router.py`](./router.py), [`ee/auth.py`](./auth.py) & [`ee/store.py`](./store.py):**
  - Runtime `KODERA_EDITION=enterprise` gate and `/api/v1/ee/*` HTTP dispatcher (`GET /api/v1/ee/status`).
  - Single-snapshot customer authority via `resolve_member_authority` (`REPEATABLE READ READ ONLY`) paired with `fence_authenticated_ee_operation` (`authority_revision` + `privacy_account_cutoff` and `privacy_erasure_cutoff` advisory locks, locking `identity_user` with `FOR SHARE` and dependent `orgs_organisation` and `orgs_membership` rows with `FOR SHARE ... NOWAIT`, rolling back and returning a typed `409 authority_fenced` on contention).
  - Operator-migrated PostgreSQL schema (`apps/server/apps/orgs/migrations/0032_ee_enterprise_store.py`): 12 sequence-free `ee_*` tables with zero runtime `CREATE TABLE` DDL, narrow `kodera_api` column/table grants (`apps/server/core/db/api_writer_role.py`, strictly `SELECT` + `INSERT` append-only on `ee_audit_ledger` and `ee_audit_signing_key`), and Core organisation/account privacy erasure integration (`privacy_purge_core`, `privacy_complete_erasure`, `privacy_purge_account_core`, `privacy_complete_account_erasure`).
  - Validated `KODERA_EE_AUDIT_SIGNING_SEED` root material (`apps/server/config/environment.py`) with HKDF-SHA256 per-tenant Ed25519 key derivation and append-only historical public-key registry (`ee_audit_signing_key`) so previously issued compliance bundles remain server-verifiable across secret and signing-key rotations without retaining obsolete private keys or trusting caller-supplied manifest keys.
- **[`ee/saml/`](./saml/__init__.py) — SAML 2.0 Corporate Federation & Multi-IdP SSO (`/api/v1/ee/sso/saml/*`):**
  - Public SAML 2.0 protocol endpoints (`GET .../metadata`, SP-initiated `GET|POST .../login`, and IdP-signed `POST .../acs`) plus Bearer-authenticated, authority-fenced tenant admin IdP management (`GET|POST .../providers`).
  - Hardened XML security (`ee/saml/xml_security.py`): rejects `DOCTYPE`, `!ENTITY`, processing instructions, comments, XInclude, non-UTF-8 BOMs, and unknown entities prior to parsing; enforces W3C Exclusive XML Canonicalization (`exc-c14n#`), RSA-SHA256 / ECDSA-SHA256 signature verification, XSW1-XSW8 structural defenses, PostgreSQL atomic `RelayState` consumption and Assertion `ID` replay caching, and tenant-verified email domain enforcement.
- **[`ee/scim/`](./scim/__init__.py) — RFC 7643 / RFC 7644 SCIM 2.0 Provisioning (`/api/v1/ee/scim/v2/*`):**
  - Constant-time SHA-256 hashed per-tenant SCIM bearer tokens persisted in `ee_scim_token` with scope enforcement, cross-tenant isolation, privacy-cutoff refusal, and instant multi-worker token revocation.
  - `/ServiceProviderConfig`, `/Schemas`, `/ResourceTypes`, `/Users`, and `/Groups` with `application/scim+json` responses, linear-time `filter` + `startIndex`/`count` pagination, normalized `ee_scim_user` / `ee_scim_group` / `ee_scim_group_member` / `ee_scim_session` / `ee_scim_deprovision` storage, and Okta / Microsoft Entra ID `PatchOp` compatibility.
  - Strictly tenant-scoped Core authority & person-isolation composition: SCIM and SAML never link or reuse a global `identity_user` across tenants by contact `email` or `userName` (creating a fresh person root whenever no already-authorized `(organisation, issuer)` `Identity` exists in the target tenant), never mutate global `identity_user.enabled`, refuse (`403`) provisioning or reactivation of globally disabled or cutoff-erased accounts and deprovisioning/deletion of `org_owner` memberships with atomic transaction rollback, and isolate lifecycle transitions (`orgs_membership.state`, `outbox_realmaccess`, and `EngineMemberSet`) to the target `organisation_id` so sibling-tenant memberships sharing an explicitly linked person root remain unaffected.
- **[`ee/audit_export/`](./audit_export/__init__.py) — Tamper-Evident Signed Compliance Audit Exports (`/api/v1/ee/compliance/audit-exports/*`):**
  - Authority-fenced tenant-admin append-only SHA-256 hash-chained audit ledger (`prev_hash -> entry_hash`) with detached Ed25519 (and HMAC-SHA256 fallback) manifest signatures over NDJSON and CSV compliance bundles (`SOC2`, `ISO27001`, `SECNUMCLOUD`), streaming export, date/actor filters, PII redaction by default (`redact_pii=True`, `org_owner` required for unredacted export), historical key-id lookup via `ee_audit_signing_key` on `/verify`, and standalone offline CLI verifier requiring an explicit pinned trust key:
    ```bash
    PYTHONPATH=. python3 -m ee.audit_export.verify --bundle export.ndjson --manifest manifest.json --public-key tenant-ed25519.pub.pem
    ```
- **[`ee/billing/`](./billing/README.md) — Commercial Pricing, Autopilot Warm Pool & Enterprise Purchase Orders (`/api/v1/ee/billing/*`):**
  - Exact integer minor-unit commercial price schedules ([`pricing.py`](./billing/pricing.py)) enforcing a `4400 bps` (`44.0%`) minimum gross-margin floor, deterministic Autopilot warm-pool sizing, replenishment planning, unhealthy-slot eviction, and idempotent checkout claim ([`warm_pool.py`](./billing/warm_pool.py)).
  - Operator-migrated sequence-free PostgreSQL tables (`apps/server/apps/billing/migrations/0024_enterprise_billing_tables.py`: `ee_billing_sequences`, `ee_billing_warm_pool_slots`, `ee_billing_purchase_orders`), Purchase Order lifecycle (`draft` -> `issued` -> `countersigned` -> `invoiced` -> `paid` / `expired`) verified against persisted Core ledger rows (`billing_invoice`, `billing_payment`), customer-only countersign signatory ownership (`countersigned_by_user_id`), held `FOR SHARE ... NOWAIT` authority and exact `staff_operator` / `staff_support` role fences ([`api.py`](./billing/api.py), [`storage.py`](./billing/storage.py), [`purchase_orders.py`](./billing/purchase_orders.py)), and Core organisation/account privacy erasure hooks.
