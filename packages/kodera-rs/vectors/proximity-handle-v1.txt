# Kodera proximity sender handle v1: the pseudonym shown for a check-in.
#
# A proximity frame carries its sender's device public half, never a name. What a client shows
# next to a check-in is a handle: one the member picked for this purpose (`dedicated`) or one
# derived for the frame's sender inside one organisation (`generated`). A real name is never
# required and never travels in a frame.
#
# A handle is a DISPLAY LABEL. It is never an identity and never an authorisation input: identity
# stays the Ed25519 signing key, and the roster and the signature decide what is admitted. Two
# senders can show the same handle, by accident or on purpose; a client that lists a roster
# disambiguates them with a fingerprint of the signing half (see `roster` below).
#
# A handle is 3 to 24 characters matching ^[a-z0-9]+(?:-[a-z0-9]+)*$ (ASCII only, so characters
# and bytes agree). A generated handle is
#   <adjective>-<noun>-<9 characters of the alphabet below>
# where d = HMAC-SHA256(key = the organisation's 32-byte beacon salt,
#                       message = "kodera-proximity-handle-v1:" || 32 sender bytes),
# the adjective is entry d[0] & 31, the noun is entry d[1] & 31, and the 9 characters spell, most
# significant first, the top 45 bits of d[2..8] in the alphabet 0123456789abcdefghjkmnpqrstvwxyz.
# That is 55 bits of the digest, the most the 24-character bound leaves beside the longest word
# pair. The organisation salt binds a handle to one organisation: the same sender shows another
# handle elsewhere, so handles are not linkable across organisations and one searched for in one
# organisation is worth nothing in another. The label is hashed for display only; it is not part
# of the frozen frame v1 and signs nothing.
#
# A fingerprint is the lowercase hex of SHA-256("kodera-proximity-fingerprint-v1:" || 32 sender
# bytes). When two or more distinct provisioned senders of one roster resolve to the same handle, each is
# shown as `<handle> [<fingerprint prefix>]`: 8 hex characters, lengthened two at a time until
# the prefixes of that group differ. A sender whose handle is unique in the roster shows no
# fingerprint.
#
# Rust (`packages/kodera-rs/src/proximity_handle.rs`), Swift (`apps/ios/packages/KoderaDomain`)
# and Kotlin (`apps/android/domain`) read this file and agree with every line.
#
# Grammar, one entry per line, fields separated by single spaces:
#   bound <name> <value>
#   origin <slug>
#   adjective <index> <word>
#   noun <index> <word>
#   valid <handle>
#   refuse <name> <utf8_hex|->          (`-` is the empty string)
#   generated <organisation_salt_hex> <sender_hex> <handle>
#   roster <case> <organisation_salt_hex> <sender_hex> <dedicated_handle|-> <handle> <fingerprint|-> <present|absent>
# A `roster` case is every line sharing its name, in order: every PROVISIONED sender of one
# roster, the handle each resolves to and the fingerprint prefix it is shown with (`-` for
# none). `present` senders have checked in and are listed by a client; `absent` ones have not.
# The groups are computed over every provisioned sender, never over those seen so far: a sender
# whose handle equals an absent member's already shows its fingerprint, so it cannot pass for the
# absent member, and no label changes when that member appears.
# Blank lines and lines starting with `#` are ignored. Any other line is an error.
