# Kodera extensions

Status: Reference implementations

Every directory here is a **reference implementation** of an extension built on
[`@kodera/extension-sdk`](../packages/extension-sdk): a manifest, a signed-webhook handler,
slash commands where the manifest declares them, and tests. Read them as worked examples of
the SDK, not as integrations you can switch on.

- **Exercised with synthetic fixtures only.** The tests run against the SDK's in-memory
  harness. No implementation here has been run against a provider's own service, and a
  provider's name in a directory describes the payload shape the example models, not an
  endorsement by that provider.
- **Not installed, hosted or connected by this repository.** Kodera's server has no extension
  registry, installer or webhook delivery yet, so nothing registers these manifests or
  calls their handlers for a workspace. Each manifest's `webhookUrl` is a reserved
  documentation host.
- **Workspace templates name them as an intent.** A template of
  [`deploy/community`](../deploy/community/README.md) may list one of these directories under
  `connectors`; that records what an operator plans to wire, nothing more.

## Changing an extension

```bash
node extensions/catalog.mjs           # regenerate catalog.json and the table above
node extensions/catalog.mjs --check   # what CI runs, through `npm run test:sdk`
```

The check refuses a catalogue that differs from the manifests, a second manifest file in one
directory, a `webhookUrl` outside the documentation hosts, a package description or README
that drops the *Reference implementation* label, and wording that presents an extension as
endorsed by a provider or already connected for a workspace.

To start your own, copy [`hello-webhook`](./hello-webhook/README.md).
