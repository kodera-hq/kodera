# Architecture decision records

Status: Active

Every architecture decision record (ADR) of the monorepo, in one list. A record stays in the
package it governs: this index links to it there and never copies or moves it.

## Identifiers

Each package numbers its records from `0001`, so a bare "ADR-0003" is ambiguous across the
monorepo. Outside the package that owns a record, cite it by its prefixed identifier:

| Prefix | Records of | Directory |
| :--- | :--- | :--- |
| `SRV-ADR-NNNN` | the server control plane | [`apps/server/docs/adr/`](../../apps/server/docs/adr/README.md) |
| `WEB-ADR-NNNN` | the web client | [`apps/web/docs/adr/`](../../apps/web/docs/adr/README.md) |
| `TOK-ADR-NNNN` | the design tokens | [`packages/design-tokens/docs/adr/`](../../packages/design-tokens/docs/adr/README.md) |

An identifier is the prefix and the number in the record's file name. It never changes: a
superseded record keeps its number and says which record replaces it. A record's status
(proposed, accepted, superseded) is written in the record itself, which is the only place it
is kept; this index does not repeat it.

Inside a package, "ADR-0003" keeps meaning that package's own record. In the root documents,
`ADR-0003` and `ADR-0018` without a prefix are the server's (`SRV-ADR-0003`, `SRV-ADR-0018`).

Cross-cutting protocol changes start as an RFC in [`docs/rfcs/`](../rfcs/RFC-0001-emergency-ble-channel.md),
as [`GOVERNANCE.md`](../../GOVERNANCE.md#3-architectural-changes-docsrfcs) describes.

## Adding a record

1. Write it in the package's own `docs/adr/` directory, from that directory's template, with
   the next free number.
2. Regenerate the table above and check it:

   ```bash
   python3 scripts/ci/check-docs-truth.py --write-adr-index
   python3 scripts/ci/check-docs-truth.py
   ```

The check runs on every pull request. It refuses a record that this index does not list, a
listed record that does not exist, an identifier that does not match the file it links to,
and a title that no longer matches the record's own.
